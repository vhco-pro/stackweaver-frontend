# Setup Guide

This guide walks you through setting up the Stackweaver Orchestration Platform for local development.

## Prerequisites

- **Docker** and **Docker Compose** (latest version)
- **Make** (for convenience commands)
- **Git** (for cloning the repository)
- **Go 1.24+** (for backend development, optional)
- **Node.js 18+** (for frontend development, optional)

## Quick Start

### 1. Clone the Repository

```bash
git clone <repository-url>
cd iac-orchestration-platform
```

### 2. Configure Environment Variables

> [!IMPORTANT] **Required Environment Variables**:
> The following variables are required by stackweaver. For convenience they are generated at runtime by the `zitadel-init` init-container.
> ```env
> ZITADEL_LOGIN_SERVICE_USER_TOKEN=your-service-user-token
> ZITADEL_API_CLIENT_ID=your-api-client-id
> ZITADEL_API_CLIENT_SECRET=your-api-client-secret
> ZITADEL_FRONTEND_CLIENT_ID=your-frontend-client-id
> ZITADEL_FRONTEND_CLIENT_SECRET=your-frontend-client-secret
> ```

When using the compose stack, you need to create an empty `.env` file in the `deploy/` directory:

```bash
cd deploy
touch .env
```

### 3. Start the Stack

From the project root:

```bash
make fresh
```

This command:
1. Stops and removes all containers, volumes, and networks
2. Builds necessary Docker images
3. Starts infrastructure services (PostgreSQL, Redis, MinIO)
4. Starts Zitadel
5. Waits for Zitadel to be ready
6. Runs Zitadel initialization script
7. Starts application services (API, Frontend, Login UI)

**Alternative**: Manual startup

```bash
cd deploy
docker compose up -d postgres redis minio
docker compose up -d zitadel
# Wait for Zitadel to be ready (check logs)
docker compose run --rm zitadel-init
docker compose up -d api frontend login-ui
```

### 4. Access the Application

Once all services are running:

- **Frontend**: http://localhost:5173
- **API**: http://localhost:8022
- **Zitadel Console**: http://localhost:8080/ui/console
- **Login UI**: http://localhost:3000/ui/v2/login
- **MinIO Console**: http://localhost:9001 (minioadmin/minioadmin)

### 5. Initial Login

1. Navigate to http://localhost:5173
2. Click "Sign in with Zitadel"
3. Use the default admin credentials:
   - **Username**: `admin@ZITADEL.localhost`
   - **Password**: `Password1!`

**Note**: Change the default password after first login!

## Detailed Setup

### Zitadel Configuration

Zitadel is configured via `deploy/zitadel-defaults.yaml`. See the file for complete configuration.

**Important**: The `ExternalDomain` must be `localhost:8080` for browser access. The init script handles the internal Docker networking.

**Reference**: `deploy/zitadel-defaults.yaml`

### Database Setup

PostgreSQL is automatically initialized with:

- **Database**: `iac_platform` (for application data)
- **Database**: `zitadel` (for Zitadel data)
- **User**: `iac`
- **Password**: `iac_password`

The database schema is automatically created via GORM's `AutoMigrate`.

### Zitadel Initialization

The `zitadel-init` script (`scripts/zitadel-init/main.go`) performs:

1. Waits for Zitadel to be ready
2. Creates an organization
3. Creates OAuth2 applications:
   - **Frontend App**: Web application with PKCE
   - **API App**: Service account for backend
4. Generates client IDs and secrets
5. Creates a Personal Access Token (PAT)
6. Writes configuration files:
   - `deploy/.env` (if not exists)
   - `frontend/.env` (with `VITE_ZITADEL_ISSUER` and `VITE_ZITADEL_CLIENT_ID`)

**Generated Files**:

- `deploy/.env`: Contains `ZITADEL_API_CLIENT_ID`, `ZITADEL_API_CLIENT_SECRET`, `ZITADEL_FRONTEND_CLIENT_ID`, `ZITADEL_FRONTEND_CLIENT_SECRET`
- `frontend/.env`: Contains `VITE_ZITADEL_ISSUER` and `VITE_ZITADEL_CLIENT_ID`

### Access pgAdmin (Optional)

pgAdmin is available at http://localhost:5050

**Login credentials:**
- Email: `admin@iac.local`
- Password: `admin`

**To connect to the PostgreSQL database:**
1. Right-click "Servers" → "Register" → "Server"
2. General tab:
   - Name: `IAC Platform DB`
3. Connection tab:
   - Host name/address: `postgres` (or `localhost` if connecting from host)
   - Port: `5432`
   - Maintenance database: `iac_platform`
   - Username: `iac`
   - Password: `iac_password`
   - Check "Save password"
4. Click "Save"

### Frontend Configuration

The frontend uses environment variables from `frontend/.env`. The `zitadel-init` script automatically generates this file with the correct values.

**Key Variables**:
- `VITE_API_URL` - Backend API URL (defaults to `http://localhost:8022/api/v2`)
- `VITE_ZITADEL_ISSUER` - Zitadel issuer URL
- `VITE_ZITADEL_CLIENT_ID` - Frontend OAuth2 client ID

**Reference**: `frontend/.env` (generated by `scripts/zitadel-init/main.go`)

**Development Mode**: The Vite dev server proxies `/api` requests to `http://localhost:8022` to avoid CORS issues.

### Backend Configuration

The backend reads configuration from environment variables and `backend/config/config.yaml` (if present).

**Key Configuration**:
- Database connection via environment variables or config file
- Zitadel configuration via environment variables
- Storage backend configuration (MinIO, etc.)

**Reference**: See `backend/config/` directory and environment variable usage in `backend/cmd/api/main.go`
  user: iac
  password: iac_password
  dbname: iac_platform
  sslmode: disable

auth:
  zitadel:
    issuer: http://localhost:8080
    client_id: ${ZITADEL_API_CLIENT_ID}
    client_secret: ${ZITADEL_API_CLIENT_SECRET}
```

Environment variables are loaded from `deploy/.env`.

## Development Workflow

### Running Services Individually

**Start only infrastructure**:
```bash
docker compose up -d postgres redis minio
```

**Start only Zitadel**:
```bash
docker compose up -d zitadel
```

**Start only application services**:
```bash
docker compose up -d api frontend login-ui
```

### Viewing Logs

**All services**:
```bash
docker compose logs -f
```

**Specific service**:
```bash
docker compose logs -f api
docker compose logs -f frontend
docker compose logs -f zitadel
```

### Rebuilding Services

**Rebuild and restart a service**:
```bash
docker compose up -d --build api
```

**Rebuild all services**:
```bash
docker compose build
docker compose up -d
```

### Database Access

**Connect to PostgreSQL**:
```bash
docker exec -it iac-postgres psql -U iac -d iac_platform
```

**Dump Zitadel database**:
```bash
docker exec iac-postgres pg_dump -U iac -d zitadel --clean --if-exists --create --format=plain > zitadel-dump.sql
```

**Restore database**:
```bash
docker exec -i iac-postgres psql -U iac -d zitadel < zitadel-dump.sql
```

### Clean Restart

**Full cleanup and restart**:
```bash
make fresh
```

This removes all containers, volumes, and networks, then rebuilds and starts everything fresh.

**Manual cleanup**:
```bash
docker compose down -v --remove-orphans
docker volume prune -f
docker compose up -d
```

## Troubleshooting

### Zitadel Not Starting

**Check logs**:
```bash
docker compose logs zitadel
```

**Common issues**:
- Database not ready: Wait for PostgreSQL to be healthy
- Port conflict: Ensure port 8080 is not in use
- Configuration error: Check `zitadel-defaults.yaml`

### Init Script Failing

**Check init script logs**:
```bash
docker compose logs zitadel-init
```

**Common issues**:
- Zitadel not ready: Wait longer for Zitadel to start
- Network error: Ensure `ZITADEL_ISSUER` and `ZITADEL_INTERNAL_ADDR` are correct
- PAT not found: Check if PAT file exists in `zitadel-pat` volume

### Frontend Not Loading

**Check frontend logs**:
```bash
docker compose logs frontend
```

**Common issues**:
- Build error: Check Node.js version and dependencies
- CORS error: Ensure Vite proxy is configured correctly
- Environment variables: Check `frontend/.env` exists and has correct values

### API Not Responding

**Check API logs**:
```bash
docker compose logs api
```

**Common issues**:
- Database connection: Check PostgreSQL is running and accessible
- Authentication error: Check Zitadel configuration and client credentials
- Port conflict: Ensure port 8022 is not in use

### CORS Errors

**Development**: The Vite proxy should handle CORS automatically. If you see CORS errors:

1. Check `vite.config.ts` has the proxy configured
2. Ensure frontend is using relative URLs (`/api/v1`) in development
3. Check backend CORS middleware allows the frontend origin

**Production**: Configure CORS in the backend middleware to allow your frontend domain.

### Token Validation Errors

If you see "invalid token" errors:

1. Check token is not expired (tokens expire after 1 hour by default)
2. Verify Zitadel issuer URL matches in frontend and backend
3. Check Zitadel JWKS endpoint is accessible: `http://localhost:8080/oauth/v2/keys`
4. Ensure client ID matches in frontend and backend

## Production Deployment

### Environment Variables

Set the following environment variables in production:

```env
# Database
DATABASE_URL=postgresql://user:password@host:5432/iac_platform?sslmode=require

# Zitadel
ZITADEL_ISSUER=https://zitadel.yourdomain.com
ZITADEL_API_CLIENT_ID=your-client-id
ZITADEL_API_CLIENT_SECRET=your-client-secret

# Frontend
VITE_API_URL=https://api.yourdomain.com/api/v1
VITE_ZITADEL_ISSUER=https://zitadel.yourdomain.com
```

### Security Considerations

1. **TLS/HTTPS**: Enable TLS in production (set `TLSMode: enabled` in Zitadel config)
2. **Secrets**: Use a secrets manager (Vault, AWS Secrets Manager, etc.)
3. **Database**: Use strong passwords and enable SSL
4. **CORS**: Restrict CORS to your frontend domain only
5. **Rate Limiting**: Adjust rate limits for production load
6. **Token Expiration**: Configure appropriate token expiration times

### Scaling

**Horizontal Scaling**:
- Run multiple API instances behind a load balancer
- Use a shared PostgreSQL database
- Use Redis cluster for distributed caching/queuing

**Database Scaling**:
- Use PostgreSQL read replicas for read-heavy workloads
- Consider connection pooling (PgBouncer)
